# Island

Integrated [Luci](https://github.com/ElhamSadiqi/Luci) at commit `2627227ab797cf7933c5f39925911429e2ccf49b`. MIT license retained in `LICENSE`. Island runs from its own `shell.qml`; the root Caelestia exports stay attached to Caelestia.

## Compositors: Hyprland and niri

Island runs under both Hyprland and niri. **Any future change that touches Hyprland or niri must take the other compositor into account**: a new `hyprctl` call, `Quickshell.Hyprland` binding, `hl.*` dispatch or Hyprland rule needs a niri path (or an explicit, documented "not available on niri" gate), and a new `niri msg` call needs the Hyprland path to keep working unchanged. Hyprland behaviour is the reference and must not regress.

- `services/Compositor.qml` detects the compositor (`ISLAND_COMPOSITOR=niri|hyprland` forces it; otherwise `XDG_CURRENT_DESKTOP`, then `HYPRLAND_INSTANCE_SIGNATURE`, then `NIRI_SOCKET`; the desktop name is read first because a nested session inherits the other compositor's variables, and Hyprland wins when both sockets are set with no desktop name). QML should ask `Compositor` (`niri`, `focusedMonitorName`, `monitorFor()`, `workspaces`, `focusedWorkspace`, `hasFullscreen()`, `focusWorkspace()`, `toggleOverview()`, `spawnFloating()`, `recordMonitors()`/`recordClients()`) rather than importing `Quickshell.Hyprland` directly. Under Hyprland these forward to `Quickshell.Hyprland` unchanged.
- `services/NiriService.qml` keeps one `niri msg --json event-stream` open (workspaces, windows, keyboard layout, overview) and reads `niri msg --json outputs` when the screens change. `services/NiriModel.js` holds the pure parsing and the conversion to the Hyprland-shaped records the rest of Island consumes, so it can be tested without niri. `ISLAND_NIRI_BIN` replaces the `niri` binary (for tests).
- Shell scripts under `integration/` and `scripts/` pick the compositor with the same rules and must keep both branches.
- Features with no niri equivalent are gated with `Compositor.has*` flags and hidden or made inert rather than faked: Layout, Workspace Axis and Shell mode menus, the Keybinds list, the Displays editor (the shared hyprmoncfg backend is Hyprland-only), window-rounding sync, Night Light (hyprsunset), and special workspaces. Add new Hyprland-only features to that list.
- niri shortcuts: `integration/niri-binds.kdl` is the counterpart of `integration/hyprland.lua` (paste its `binds` block into niri's `config.kdl`; needs `spawn-sh`, niri 25.08+). The installer, `toggle-shell-mode`, `workspace-presentation` and the Hyprland lock launchers are Hyprland session tooling and are not run under niri.
- On niri, a floating spawn (the wallpaper folder button) cannot carry window rules, so `NiriService.spawnFloating()` floats, sizes and centres the first new window whose app id matches. Recording a window computes its rectangle from niri's tile position, so a window scrolled out of view cannot be recorded.
- Checks: `node island/integration/tests/niri-model.js` (parsing and conversion) and `bash island/integration/tests/niri-compositor` (the services against a mock `niri`; set `ISLAND_NIRI_BIN` to point Island at another binary). Neither needs niri installed, and neither replaces a run on a real niri session, which has not been done yet.
- On niri, workspace numbers are the index on each monitor, only workspaces that exist are listed (niri creates and drops them itself), and panels close on an outside click through a full-screen input catcher because niri has no focus-grab protocol.

Install desktop integration with `./island/integration/install --dry-run`, then `./island/integration/install`. The installer checks the inspected utility hashes, preserves existing hard links, saves backups in `~/.local/state/island/install-backups/`, registers `~/.config/hypr/island-mode-keybindings.lua`, and initializes Island state. It does not switch the running shell.

Use `./island/integration/install --utilities-only --dry-run`, then `./island/integration/install --utilities-only`, to update the desktop utilities without initializing themes or changing Hyprland's module registration.

The compact Island displays only the clock. The theme section shows the static theme name, or `dynamic`. The expanded view has a control center button with a sliders icon and a three-dot Menu panel.

Menu → **Keybinds** (Super + Alt + K) lists active global Hyprland and Island mode shortcuts with descriptions. Search by description or key combination; click a row or use Up/Down and Enter to run it through Hyprland. Escape closes the panel. The panel resolves the current binding again before execution, including Lua callbacks after a config reload. `island/integration/keybinds run ID --dry-run` prints the dispatch command without running it. Run `bash island/integration/tests/keybinds` for isolated backend and panel checks.

Menu displays a grid of cards, 2×2 by default. Settings → Menu sets its rows (`menuRows`) and columns (`menuColumns`), each 2-4, so the largest grid is 4×4; extra columns widen the panel instead of shrinking cards. Pin as many submenus as the grid holds with their pin buttons; filled pins are saved automatically in Island's `menuPinnedEntries` setting (up to 16). Search results use the same grid, and each mouse-wheel step scrolls one row. The first rows × columns cards show without searching (pins, then random submenus selected each time Menu opens); the mouse wheel scrolls one row at a time through the remaining submenus, and search is not needed. The search icon beside **Menu** reveals a search field and slightly extends the panel. Search starts hidden and finds every submenu, including AI Usage, Calendar, Timer, Layout, Session, Control Center, Audio devices, Wi-Fi, Bluetooth, Clipboard, Chromack, Network and Disk speed tests, all Settings pages, and Shell mode. Settings pages appear only once you type a query, labelled **Settings > <page>** (for example **Settings > Clock**); a blank search and the default grid hide them unless you pinned one. Search matches titles, descriptions, and related terms. Use **/** to toggle search, **Ctrl+F** to reveal or focus search, **Down** to focus results, arrows to select, and **Enter** to open. **Escape** first hides search, then closes Menu. Run `bash island/integration/tests/menu` for isolated menu interaction and persistence checks.

Menu → **Layout** (Super + Alt + L, Menu search for "layout", "tiling" or a layout name, or `scripts/quickshell -p island/shell.qml ipc call island openLayoutSwitcher`) is the shell-panel version of `~/bin/menu-layout` and looks like the Shell mode switcher: a search field above one button per layout (Dwindle, Scrolling, Master, Monocle, Grid, Spiral, Manual, Center-Stack), with the current layout highlighted and labelled **Active layout**. Click a layout, or select it with arrows and **Enter**. A successful change closes the panel; an error stays visible so you can retry. The key press toggles the panel, and **Escape** closes it.

Menu → **Workspace Axis** (Super + Alt + W, Menu search for "workspace axis", or `scripts/quickshell -p island/shell.qml ipc call island openWorkspaceAxis`) selects Horizontal or Vertical, with the current choice marked **Active axis**. While Scrolling is active, Workspace Axis disappears from Menu, including pinned cards and search, and its shortcut and IPC action cannot open the panel. Scrolling always uses Vertical; leaving Scrolling restores the axis selected before entering it.

Both selectors use `island/integration/workspace-presentation`, which saves each shell's window layout, workspace axis, and axis before Scrolling under `~/.local/state/hyprland-presentation/`. Shell switching captures the departing shell and restores the destination, including on startup and rollback. Shells without saved preferences start from the settings present before the first change. Monitor layouts and workspace assignments continue using the shared display backend.

`ISLAND_WORKSPACE_PRESENTATION_SCRIPT` overrides the helper path. `ISLAND_WORKSPACE_PRESENTATION_POLL_MS` sets status refresh while Menu, Layout, or Workspace Axis is open (default 1000 ms, clamped to 250–5000 ms). The helper accepts `status island`, `set-axis island horizontal|vertical [--dry-run]`, and `set-layout island ID [--dry-run]`. Run `bash island/integration/tests/layout` for isolated panel fixtures; it launches an offscreen shell and should be skipped when only static checks are wanted.

For checks without a running shell, use `node island/integration/tests/workspace-presentation.js`, `bash island/integration/tests/workspace-presentation`, and `bash island/integration/tests/mode-transitions`. These exercise menu gating, preference storage, shell switching, and rollback with mocked Hyprland and shell commands.

Menu → **AI Usage** shows usage quotas, reset times, credits, and provider details from `ai-usagebar`, matching Caelestia's report format. Only enabled, configured providers and accounts appear; a provider selector appears when more than one is available. The panel refreshes when opened and every five minutes, with a manual refresh and the last report retained when a refresh fails. `scripts/quickshell -p island/shell.qml ipc call island openAIUsage` toggles it from the CLI. Run `bash island/integration/tests/ai-usage` for isolated provider and panel checks.

AI Usage supports `ISLAND_AI_USAGE_BIN` and `ISLAND_AI_USAGE_CONFIG` as absolute paths for an alternate CLI and TOML configuration. `ISLAND_AI_USAGE_REFRESH_INTERVAL_SECONDS` changes polling (default 300 seconds), and `ISLAND_AI_USAGE_TIMEOUT_SECONDS` changes the command timeout (default 30 seconds).

Settings → App launcher includes **Show all apps** and **Colorize app icons**. Icon coloring defaults to off; enabling it uses Caelestia's shading-preserving foreground tint with Island's theme colors. The launcher popup contains only search, results and keyboard hints. The renderer uses the shared `Shell.AppIcons` runtime module installed by `./scripts/build-app-icons`.

Settings → Appearance has **UI** followed by **Island**. UI offers Font (`uiFontFamily`, default Noto Sans), bold text, letter spacing (0–3 px), and animation duration (0–1000 ms; zero disables these animations). Font changes text throughout Island's panels and controls. Clock and OSD each offer an **Inherit UI font** switch (`clockInheritUiFont` and `osdInheritUiFont`, default off). Enabling inheritance follows UI font changes immediately; disabling it restores that section's saved custom font. Icons keep their dedicated font.

Settings → **Displays** opens the floating hyprmoncfg layout editor copied from Caelestia at **1600×900**, with Island's colours and UI font. Repeated opens focus the existing window and retain unsaved edits. Layouts, workspace assignments, automatic/manual profile selection and monitor nicknames use the [shared display backend](../shared/display/README.md), daemon and profile store across all shell modes. The preview confirmation guard survives editor closure and monitor changes; unconfirmed layouts roll back. Opening the editor only reads the shared state. `scripts/quickshell -p island/shell.qml ipc call island openDisplays` opens it from the CLI; `closeDisplays` closes it.

Island offers monitor selection, compact Width and Height, Top margin, Bottom margin, Corner radius, Border width (0–4 px), Opacity, Panel animation (Morph or Classic), and Expansion duration (0–1000 ms). Width defaults to 160 px and clamps to the measured clock width plus 2 px of padding on each side, inside any border. Height defaults to 33 px and grows to fit the clock. The bottom margin keeps its saved `reservedSpaceBelow` setting. OSD and workspace transitions retain their own animation settings. **Panel animation** (Settings → Appearance → Island, saved as `panelAnimationStyle`) picks how Island switches between panels. **Morph** (default) reshapes the capsule's width, height and corner radius together over Expansion duration on one front-loaded curve (cubic-bezier 0.16, 1, 0.3, 1, no overshoot; compact ↔ expanded hops run at 62% of it). The incoming panel fades in (at 60% of the UI Animation duration) only as the capsule nears its target size, and never re-dims on relayout. **Classic** is the earlier animation: the width overshoots, the height eases out, the corner radius snaps and panels swap in at full opacity. OSD and workspace transitions are the same in both. A duration of 0 disables the matching animation. Run `bash ./island/integration/tests/workspaces` (it includes `panel-morph-views.qml`) for the morph and classic checks.

**Hover to expand** is on by default. Turn it off to expand and pin the compact Island with a left click anywhere on it, including the clock. With hover expansion enabled, clock clicks keep switching the time format; the expanded clock retains that action in both modes. Hover never replaces a Media panel opened by click, and while the clock is showing a lyric line a click has to bring the clock back before hovering expands the Island again (move the cursor off and back on). Lyrics in the clock belong to the Island on one monitor: only a click on that Island, or a panel opening on it, clears them.

**Notch mode** (Settings → Appearance → Island, saved as `notchMode`, default off) hangs Island from the top edge of the screen: the top margin is ignored, the top corners flare outward in concave curves, and the bottom corners stay rounded. Every panel and the OSD drawer use the same outline, since they all draw inside the capsule. **Settings → Desktop** has **Screen corners** (`screenCorners`, default off), which rounds the screen corners in Island's background color and opacity, and **Screen corner radius** (`screenCornerRadius`, 4–64 px, default 24), shown while corners are on. While Island is the active shell mode, Hyprland's `decoration:rounding` is set to the same radius (`rounding_power` 2, a circular corner) the way Caelestia syncs its window rounding, and reapplied after every config reload. Turning corners off reloads the Hyprland config to restore the configured rounding. The corners are click-through and hidden while a window is fullscreen.

Run `bash ./island/integration/tests/appearance-settings` for isolated rendered controls, clock width clamps at different fonts and time formats, actual slider/switch clicks, height and desktop reservation, borders, UI typography and animations, persistence, input validation, and dry-run checks.

Settings → Clock opens a dedicated panel for 12-hour time (AM/PM), font family, size (8–40 px), and bold weight, with a live preview. Clicking the compact or expanded clock switches between 12-hour and 24-hour time; the shared `clock12Hour` setting saves automatically and defaults to false. The expanded clock stays on the compact clock's center line, with the clock/date group centered vertically alongside the controls. The compact clock grows to fit larger text and updates the reserved height. Settings → OSD opens a separate panel for the volume, brightness, nightlight, and keyboard font, size, weight, icon size, percentage visibility, slider width/thickness/rounding, value animation, entrance/exit animation, and display duration. These settings save automatically; Clock and OSD fonts can be customized independently when inheritance is off.

The expanded Island has a thin pill in the theme's accent color centered at its bottom edge, under the clock. Clicking it drops the Island down to reveal the workspace section, and the pill slides down with the bottom edge (clicking again, collapsing the Island or opening another panel closes it; the clock does not move). Everything sits on one line: the persistent workspaces, then the special workspaces, then the two overview buttons, centred as plain buttons with a wider gap between the groups (no capsules or separators). The workspaces are the same set the workspace dots use, so Settings → Workspaces' count and persistence apply; click one to switch. They follow the switcher style by default: with the **dots** style they show the same dots as the workspace OSD (clickable, with a larger hit area), otherwise numbered buttons. Settings → Workspaces → **Expanded switcher style** has an **Inherit switcher style** switch (`workspaceExpandedInheritStyle`, default on); turn it off to pick this row's own **Style** (`workspaceExpandedStyle`: default or dots) and **Dot size** (`workspaceExpandedDotSize`, 1–31 px, default 8) independently of the OSD. The special workspaces and overview buttons stay icon buttons in every style. The special workspaces section always shows Discord, Media (Spotify), Scratchpad (pencil) and Social (Instagram), followed by any other special workspace that exists or is named by a workspace rule, with a generic star icon (Caelestia's `aether` and `nexus` are never listed). A special workspace with no window in it is greyed out; the one currently shown is highlighted. Clicking one runs `~/bin/hypr-focus-special-workspace <name>`, the same helper as the Hyprland keybinds. The two overview buttons at the end run `~/bin/hypr-toggle-workspace-control` and `~/bin/hypr-toggle-mission-control` and then collapse the Island. While the section is open the workspace OSD is not shown on that Island (the section already shows the active workspace); when it is closed the regular workspace OSD appears. Volume, brightness, nightlight and keyboard OSDs drop below the section in the usual attached drawer. Run `bash ./island/integration/tests/workspaces` (it includes `workspace-panel-views.qml`) for the checks.

Under the workspaces, the same section holds screen recording controls built on `gpu-screen-recorder`, the way Caelestia uses it: a record button, pause/resume and stop (dimmed until a recording is running) and the running time (`--:--` when idle). While a recording runs, a red dot to the right of the clock (compact and expanded) blinks, and holds still and dim when paused; click it to stop the recording. A left click on the record button starts recording again with the last choices (mode, monitor, webcam and its place, sound, all remembered across restarts) and folds the Island away; if those can't be reused, such as a window that has since closed, it opens the popup instead, as does a right click. The popup draws every monitor to scale with viewfinder brackets around what will be recorded. Choose **Region** (drag over any part of any monitor after pressing the button; Escape cancels), **Screen** (pick the monitor) or **Window** (any window on a showing workspace), and optionally add the **Webcam** (a quarter-size overlay: drag it anywhere inside the preview, it only stops at the edges) and **Sound** (system audio). Hyprland on Wayland has no native window capture in `gpu-screen-recorder`, so a window is recorded as the screen rectangle it occupies when you press start: it does not follow the window if it moves, and anything covering it is recorded too. Settings → Screen recording sets the container (MP4 or MKV; WebM needs a VP8 encoder many GPUs lack), where recordings are saved (default `Videos/Recordings`; type a path or press **Choose folder…**, which runs `zenity --file-selection --directory` with `GTK_USE_PORTAL=1`, so the folder picker is the desktop's file chooser portal (the settings panel folds away while it is open and returns when it closes); `ISLAND_RECORD_PICKER` replaces `zenity`), quality, frame rate, cursor and which camera to use. The recorder runs detached through `island/integration/screen-record start|stop|pause|status`, which keeps its state in `$XDG_RUNTIME_DIR/island-screen-record/state.json`, so reloading the shell mid-recording keeps the timer and buttons right, and the file only appears in the recordings folder once the recorder has finished writing it. `qs ipc call island toggleRecording` stops a recording or opens the popup (also `stopRecording`, `pauseRecording`, `openRecordOptions`) for a keybind. Run `bash island/integration/tests/screen-recording` for the settings, script, popup and control checks.

Menu → **Timer** (search the Menu for "timer" or "countdown", or `scripts/quickshell -p island/shell.qml ipc call island openTimer`) sets countdowns. The panel is wide rather than tall: the dial, the minute buttons and the label are on the left; Indefinite alert, Alert sound and Allow snooze, with their dropdowns, on the right; Start and the running timers run the full width below. The face is a kitchen timer's: the wedge shows the time dialed in, a full turn being an hour. Drag the ring to turn it by the minute, type digits like a microwave (`1` `5` `0` `0` is 15:00, `9` `0` is 1:30; Backspace drops a digit, Delete clears), or add time with **+1 min**, **+5 min** and **+10 min**. Add an optional label, turn on **Indefinite alert** if you want, turn on **Alert sound** to pick the sound the timer plays when it ends (Alarm clock, Bell, Complete, Message, Ringtone or Attention, from the freedesktop sound theme in `/usr/share/sounds`; each one in the dropdown has a play button, and so does the dropdown itself for the chosen one, since nothing plays on its own), turn on **Allow snooze** to choose how long a snooze lasts (1, 5, 10, 15 or 30 minutes), and press **Start** or Enter; the form then clears so another timer can follow, and up to 20 run at once, each listed under the form with its remaining time, a button to pause or resume it and a button to cancel it. A paused timer keeps its time, never goes off and is shown after the running ones (the island shows the running timer that ends first, and goes muted only when all are paused); the Control Center tile pauses and resumes them all, as does `qs ipc call island toggleTimerPause`. While a timer runs it replaces the clock on every Island, compact and expanded, as the remaining time in the clock's own font followed by a ring that drains with the time left, and a muted `+N` when more are running; the one ending first is shown, the ring and time turn the warning colour for the last ten seconds, and a click on the expanded Island's timer opens this panel. The Island keeps its width. With lyrics on the Island, the line stays and the time goes: only the ring is left, at the right edge, and the Island widens by its width if the line needs the room. When a timer ends it sends a notification titled with its label (or "Timer finished") through `notify-send`, so it appears like any app's and goes to the shared history; it breaks through Do Not Disturb, since you asked for it. A notification that expires uses Settings → Notifications' timeout; with **Indefinite alert** on at the time the timer was started, the alert has no timeout and stays until you dismiss it. Timers are kept as absolute end times in `~/.local/state/island/timers.json` (`ISLAND_TIMER_STATE` overrides), so a shell restart or a suspend does not lose or stretch them; a timer that ended while Island was not running goes off when it returns and says when it ended. The sound is played through `pw-play` (`paplay` if it is missing) alongside the notification, and an alarm repeats while its alert is up: until you press **Stop** or **Snooze**, close the alert, or a minute has passed (`ISLAND_TIMER_RING_LIMIT`, in milliseconds); a notification that expires on its own takes the sound with it. The alert has a **Stop** button when the timer has a sound and a **Snooze** button when snoozing was allowed as it started. **Stop** silences the alarm and leaves the alert open (Snooze still works after it); **Snooze** closes the alert and starts the same timer again for the snooze length, which then alerts and sounds the same way, and can be snoozed again. Only one sound plays at a time, so choosing another sound cuts off the previous one, a new alarm cuts off the one before it (**Stop** on an older alert never silences the newer one), turning **Alert sound** off stops whatever is playing, and closing the panel stops a preview (but not an alert that is ringing), and each timer keeps the sound and snooze length it was started with; the switches and the chosen sound are remembered in the same file (`ISLAND_TIMER_PLAYER` and `ISLAND_TIMER_SOUND_DIR` override the player and the folder). Only Island can alert: while another shell mode runs the timers keep counting against the clock, and one that ends meanwhile goes off, late, when Island returns. `qs ipc call island startTimer SECONDS "label" KEEP_ALERT SOUND` starts one (true if started; SOUND is a sound name such as `bell`, or `""` for silence; snoozing follows the panel's switch), `timers` lists the running ones as JSON, `cancelTimers` cancels them all and `openTimer` toggles the panel. Run `bash island/integration/tests/timer` for the logic, island, panel, alert and IPC checks; `TIMER_SHOTS=DIR` also saves screenshots.

The mute key (`XF86AudioMute`, released after a short press; a long press opens Audio Devices) runs `~/bin/knob-release --island`, which calls `scripts/volume.sh mute` so the toggle shows the volume OSD ("Muted" or the restored level) like the volume keys; Caelestia keeps `--quickshell`, which toggles mute directly. While the Control Center is open the volume and brightness OSDs are not shown, since its sliders already show those levels. Spotify's track-change notifications (app `spotify-media-controls`) show no popup while the media panel is open, or while the floating lyrics card is open and the lyrics are not also on the island clock; they are still saved to the history. Workspace, volume, brightness, nightlight, and keyboard OSDs share one exclusive panel: each new event replaces the previous OSD and restarts its display duration. Every open Island panel, including Settings and Themes, shows the current OSD in an attached drawer below its bottom edge with concave joins; compact Island uses its normal OSD display. The drawer shares Island's color, opacity, border and corner radius, and uses workspace or OSD animation settings as appropriate. The parent panel keeps its dimensions and outline throughout the drawer animation, with its contents in place. Wide OSD content scales to fit beneath the panel. Island's drawing window stays fixed to the screen while panels animate inside it, avoiding Wayland surface resizing and fractional-scale movement. A separate transparent window reserves the compact Island's desktop space; the drawing window's input mask follows only its visible panels.

Only the event's monitor displays the OSD. Volume, keyboard and nightlight use the focused Island monitor; brightness uses the monitor whose brightness changed. Events from monitors without an Island fall back to the first available Island. When only one monitor has an Island, brightness keeps its source monitor label. Brightness events replace each other rather than stacking. Per-monitor event files deliver concurrent shortcut changes into the same exclusive panel. `ISLAND_HYPRCTL_BIN` overrides monitor discovery in the shortcut adapters.

The down caret beside **Audio** reveals hidden audio options above **Output**, and turns upward while they are open; **Escape** hides them first. **Allow volume above 100%** (saved as `audioAllowOverAmplification`, default off) lets the volume slider and volume keys go past 100%, and **Extra volume** (+1–50%, saved as `audioOverAmplificationLimit`, default 50) sets how far. The Wi-Fi panel lists nearby networks with the active connection first, then by signal strength. It shows the current network or Wi-Fi state, a scan button that spins while a scan runs, speed test and QR buttons while connected, and a radio switch. The QR button closes the panel and overlays that monitor with a Wi-Fi QR code ported from Caelestia (`integration/wifi-qr` and `integration/wifi-password`, which need `qrencode`); hover the dots to reveal the password, and click outside or press Escape to fade it out. Clicking an unsaved secured network opens an inline password field; Enter or Connect submits it, and Escape or Cancel closes it first. Saved networks connect directly, the active network offers Disconnect, and saved networks offer Forget on hover. Errors from `WifiService` appear beneath the status card. `scripts/quickshell -p island/shell.qml ipc call island openWifi` toggles the panel from the CLI.

The Bluetooth panel lists Connected, Paired, and Available devices, each with a type icon, battery levels, and status text. The scan button spins while discovery runs; discovery starts automatically while the panel is open. Island owns `org.freedesktop.Notifications` while its shell mode is running, so `notify-send` and application notifications use its native popups. Desktop reservation protects the top margin and configured compact height, which grows to fit the clock. `reservedSpaceBelow` controls the visible gap to tiled window borders, accounting for Hyprland's top outer gap. ## App launcher

`SUPER+SPACE` toggles the native app launcher; `SUPER+ALT+SPACE` toggles the Island navigation menu. Type to search, use Up/Down to select, Enter to launch, and Escape to close.

**Show all apps** defaults to on. Turn it off to use `~/.config/apps.list`, including custom names, icons, and launch commands from `~/bin/app-list`. The default filtered list follows the file's order.

Open **Settings → App launcher**, or the launcher's settings button, for fuzzy/contains matching, optional description/keyword search, and separate default/search ordering. Ordering options include alphabetical, app list order, most used, recently used, and search relevance. Usage is stored in `~/.local/state/island/launcher-usage.json`.

Run `/usr/bin/bash island/integration/tests/launcher` for isolated launcher checks. `APP_LIST` and `ISLAND_APP_LIST_SCRIPT` can override the app list and helper for fixtures; `LauncherService.launch(app, true)` resolves a launch without launching or changing usage.

## Lock screen

Island uses a native Wayland session lock on every connected display, with a blurred desktop snapshot, the active Island palette, a large clock and date, a welcome to the user, a masked password field drawn as dots, an optional record-player card (now playing, transport controls and synced lyrics when available), and battery status. A small lock icon sits at the top. Desktop captures stay in memory and are discarded on unlock; when capture is unavailable, the current wallpaper is blurred instead. The PAM password stack follows Caelestia, including failed-attempt protection and GNOME Keyring unlocking. Enter submits; Escape clears the password. Authentication is shared across displays and only successful PAM authentication releases the lock.

The password field remains editable and the unlock arrow remains enabled during authentication and retry delays. Submitting a new password replaces an ongoing conversation; during the failed-attempt delay, it queues the latest input until the delay ends. A stalled conversation is cancelled after 15 seconds (`LockAuth.authenticationTimeout`) so it cannot permanently disable authentication. Successful authentication releases the lock through `WlSessionLock.locked = false`.

`SUPER+SHIFT+L`, the session menu, `~/bin/system-lock --wait`, Hypridle, pre-suspend locking, and `loginctl lock-session` all use this lock while Island mode is selected. A fresh login with Island enabled starts with `ISLAND_START_LOCKED=1` and waits for the compositor to confirm the lock before loading the bar. Island records startup per Hyprland instance, so logging out and starting Hyprland again locks even when the login session ID is reused. Switching modes or restarting Island within the current session starts unlocked.

Settings → Lock screen exposes `lockBlurRadius` (64 px, range 0–128), `lockDimOpacity` (40%, range 0–100), `lockFontFamily` (Noto Sans), `lockClockSize` (112 px, range 72–160), `lockPasswordStyle` (`default` filled circles or `random` icons, as in Noctalia), `lockShowMedia`, `lockShowBattery` and `lockShowSession` (all on), and `lockAnimationDuration` (180 ms, range 0–1000). The session buttons are the power panel's Shutdown, Reboot and Nightlight (Lock and System make no sense on a locked screen); Shutdown and Reboot ask for a second click to confirm. Time format follows the existing `clock12Hour` setting. For example, `./island/integration/island-theme --dry-run setting lockClockSize 128` previews a change.

The lock router sends one accepted request and then polls for secure confirmation; it does not issue another lock command if authentication finishes during polling. Diagnostic logs record lock requests, PAM results, and compositor state without recording passwords or PAM response contents. Island starts `hyprpolkitagent.service` on activation and releases it when leaving the mode; `ISLAND_POLKIT_SERVICE` selects another user service. GNOME Keyring unlocks through PAM, while privileged application actions use the polkit agent's own authentication prompts.

The `lock` IPC target offers `lock`, `isLocked`, and `state` (`requested:secure`). There is no unauthenticated unlock command. `island lock` is also available. `SYSTEM_LOCK_ISLAND_CONFIG` overrides the router's Island configuration path. QML file watching is disabled to prevent a source edit from replacing an active lock; use `./scripts/restart-shell` when the session is unlocked.

Run `bash ./island/integration/tests/lockscreen` for settings, persistence, validation, dry-run, all provider routes, secure-lock confirmation, the relock regression, shared and masked password input, Escape, retry delays, eight actual isolated PAM unlock cycles, time formats, and small displays. The suite uses temporary PAM configurations and a private offscreen display; it does not lock the live desktop. `mode-transitions` also covers native fresh-login locking, polkit agent lifecycle, unlocked transitions, and failed secure-lock startup. Physical lock/unlock and logout/login checks are separate.
